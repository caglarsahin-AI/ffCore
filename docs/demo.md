# PoC demo (draft)

> Draft from package 18-hazirlik (plan/18 stage 1). Package 13b owns this page and fills in the
> commands, screenshots and measured results once the PoC packages are merged. Every step uses
> synthetic data from `data/samples/`; nothing here connects to a real ticket, mail or chat system.

Each step shows one PoC use case from `plan/18-kullanim-senaryolari.md` and names the evidence
that proves it. A step whose evidence has not run yet is shown as `NOT_RUN`, never as passed.

| Step | Use case | What the audience sees | Evidence | Data |
|---|---|---|---|---|
| 1 | F1 Document assistant with sources | Ask the contract assistant about a notice period; the answer cites the contract and page. Ask something the contracts do not cover; the assistant says so instead of guessing. | `make eval` on `sozlesme-33` (≥ 80 % source-correct), `outcome_label=declined` for the unanswerable question | `data/samples/contracts/`, `eval/sozlesme-33.json` |
| 2 | F2 Ticket triage with an approved draft reply | The triage agent reads a ticket from the fake ticket desk (`ticket-desk`, test stack only, registered with auth `none`: FFCore sends it no identity), picks a class and drafts a reply. `send_reply` keeps `needs_approval`; the reply waits in the approval queue and only after approval does the desk record it. A ticket with personal data reaches the model masked. | 13b e2e: class accuracy ≥ 80 % on 20 tickets; no `send_reply` without approval (`/_sent` empty); no raw PII in the request the fake provider received. The desk itself: `test_18td_*` | `data/samples/tickets/`, `services/ticket-desk/` |
| 3 | F3 Read-only data questions | Ask the data assistant how many devices are under maintenance; it runs one SQL query on the read-only presentation DB and answers. Try a disguised write (a `DELETE` inside a CTE); it is refused with a code and the row counts do not change. | `make eval` on `sql-20` (≥ 80 %), negative e2e with `sql-write-attempts.json` | `data/samples/schema/`, `eval/sql-20.json`, `eval/sql-write-attempts.json` |
| 4 | F4 Managed LLM gateway | Send a message with a synthetic national ID through the gateway; show that the provider only ever saw a placeholder, and follow the trace from the run to the LiteLLM call to Langfuse. Quotas: `NOT_RUN` until 03c. | 13b e2e on the fake provider's recorded requests (`fake-llm` `GET /_requests`) | `data/samples/pii/` |
| 5 | F9 Expert review queue (PoC-lite) | On a finished run, an expert marks the answer correct / partly / wrong with a note; the "pending" view lists only runs not yet reviewed. A read-only user cannot review (403). | 13b e2e after 06a and 10b-poc-2 | runs of `sozlesme-33` |
| 6 | F10 Project isolation and audit trail | Log in as a member of `klinik-b` and try to open a knowledge base, document, tool, agent and run of `hastane-a`, by list, by direct link and through the API: every attempt is a 404 that does not reveal the item exists. Then follow one run of `hastane-a` from its sources to the LiteLLM call id and the Langfuse trace in one query. | 13b e2e `test_18_f10_*` (two-project seed); deleted document: the run keeps a "deleted" source reference, no content | `data/samples/projects/` |
| 7 | F11 Poisoned documents and tickets (PoC-lite) | Ask the procedure assistant (`zehirli-belge-asistani`) questions whose documents hide an instruction ("ignore your rules", "call run_sql", "write this code word"). The answer still gives the procedure's fact with its source; no canary word appears and no tool is called. A lured `run_sql` would still wait for approval. | 13b e2e `test_18_f11_*` against `poison/expected.json`; the full injection recognizer (08) is `NOT_RUN` | `data/samples/poison/`, `agents/zehirli-belge-asistani.json` |
| 8 | F12 Outage behaviour | Stop one service at a time: the model provider (the run fails with `model_unavailable`, no request leaves in airgap), Langfuse (the run completes, `trace_delivery_failed` is recorded), Qdrant (search answers with a code, the worker stays up), a full `LLM_SLOTS` (the run is queued and the wait is visible). The user always sees a coded message. | compose-level runner (13b); `NOT_RUN` until it exists | none (services are stopped) |
| 9 | F13 Document freshness | Ask the version assistant (`surum-asistani`) about a clause that changed in a contract's second version: the answer uses version 2, names the date it took effect (01.09.2025) and mentions the old value only as the previous one. | 13b e2e `test_18_f13_*` against `versions/expected.json`; the two-version diff is 04b (after the PoC) | `data/samples/versions/`, `agents/surum-asistani.json` |

After the PoC the same page gains F5 (quality monitoring, 09), F6 (long-document summary and
