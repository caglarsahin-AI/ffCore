2. `agent:<p>/<a>`'da `<p>` anahtarın projesi değilse 404 (03c-1 kuralı: anahtar yalnız kendi projesinde).
3. Stream-dışı istek de run SSE'sini içeride tüketir; `run_timeout_s` sınırı aynı.
4. `X-Resume-Run-Id`: onay konsoldan verilmişse akışı `Last-Event-ID` mantığıyla kaldığı yerden sürdürür; run başka anahtarın/projenin ise 404.
5. OpenAI `usage` son chunk'ta (`stream_options.include_usage` istenmese de; brief "son chunk'ta usage" der) — OpenAI'dan sapma, belgeli.

## Brief'te görülen çelişkiler

- Brief "Kabul kriterleri: facade ve manifest maddeleri" der ama `## Kabul kriterleri` listesinde facade maddesi yok; facade kabulü "OpenAI-uyumlu facade" bölümünün içindeki "Kabul:" paragrafında. Numaralandırmayı o paragraf + GOREV maddelerinden yaptım (tablo bölüm 5).
- Brief "`user` alanı (e-posta) ya da `X-On-Behalf-Of` JWT'si" der; 03c-1 OBO'yu `resolve_actor`'da zaten işler, e-posta yolu yok → S1.
- Brief "Eşleme yoksa aktör API anahtarının kendisidir: KB ACL `acl_role`'e göre" der ama 06a worker'ı kullanıcısız run'ı reddeder ve arama ucu ACL'yi kullanıcı üyeliğinden kurar → S2.
- Brief "usage son chunk'ta" ↔ OpenAI'da yalnız `stream_options.include_usage` ile (varsayım 5).

## Kalan riskler (plan aşaması)

- Onay sonrası `X-Resume-Run-Id` akışı: konsol resume'u kendi SSE'sini açar; facade aynı Redis Stream'i izler (06a `follow`), çift tüketim zararsız ama test edilmeli.
- Düz modelde enforce + çıktı kuralında tampon, OpenAI istemcisinde "ilk token süresi"ni uzatır (belge).
- `openai` paketinin sürüm farkı (S7) ileride şema testini kırabilir; pin ve sözleşme testi C11'i tutar.
